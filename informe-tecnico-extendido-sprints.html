Sección I · Fundamentos de Ingeniería

Evolución de la Infraestructura

Durante los ciclos 2 y 3, el proyecto RoomieMatch ha evolucionado de un prototipo conceptual a un sistema distribuido con alta fidelidad técnica. La arquitectura se ha refinado para soportar un stack moderno de JavaScript/TypeScript que garantiza una experiencia de usuario fluida y una persistencia de datos segura.

1.1 Stack Tecnológico de Vanguardia

Frontend: React 19 + Vite 6

Uso de las últimas características de React para la gestión de formularios asíncronos y transiciones de estado. Vite 6 proporciona un entorno de desarrollo instantáneo con Hot Module Replacement (HMR) optimizado.

Estilizado: Tailwind CSS 4.0

Implementación del nuevo motor de Tailwind que utiliza una arquitectura basada en CSS nativo, reduciendo el tiempo de compilación y permitiendo variables de diseño directamente en la hoja de estilos raíz.

Backend: Node.js ESM + SQLite

Arquitectura de servidor modular (ES Modules) que utiliza better-sqlite3 para una persistencia de baja latencia mediante drivers nativos en C++, ideal para el volumen de datos de una ciudad universitaria.

Sección II · Módulo Geoespacial

Geozonificación y Seguridad Urbana

Uno de los avances más significativos ha sido la integración de un Sistema de Información Geográfica (GIS) embebido. La plataforma no solo muestra anuncios, sino que analiza el entorno urbano para informar al estudiante sobre la seguridad de los barrios de Pamplona.

2.1 Implementación de React-Leaflet

Se ha implementado el componente SafetyMap.tsx, el cual utiliza la cartografía dinámica de OpenStreetMap para superponer capas de polígonos representativos.

  • Soporte GeoJSON: Almacenamiento de coordenadas poligonales de barrios (ej: Campus Principal, Humilladero, Centro) directamente en SQLite.
  • Zonificación de Riesgo: Implementación de una función de estilo dinámico que asigna colores HEX basados en el atributo safety_level (Bajo, Medio, Alto).
  • Interactividad Vectorial: Uso de eventHandlers para capturar mouseover y mouseout, proporcionando feedback visual inmediato mediante popups reactivos.

2.2 Captura de Coordenadas de Vivienda

Componente LocationPicker

Dentro del flujo de creación de publicaciones (CreateListing.tsx), se desarrolló un LocationPicker personalizado que utiliza el hook useMapEvents. Esto permite transformar un clic físico en el mapa en coordenadas lat y lng con precisión de 6 decimales.

Sección III · Lógica de Afinidad y IA

Algoritmos de Matching y Scaffolding AI

El núcleo de inteligencia del proyecto reside en el motor de compatibilidad. En el Sprint 3, se consolidó la infraestructura para el procesamiento avanzado de datos estudiantiles.

3.1 Algoritmo de Compatibilidad (Matching Engine)

Se ha desarrollado un algoritmo de filtrado colaborativo basado en perfiles de hábitos. La lógica se ejecuta en el servidor para asegurar la consistencia del ranking.

Fórmula de Afinidad Estudiantil

El sistema evalúa 5 dimensiones críticas para la convivencia:

Score = ( (Coincidencia_Horario + Ruido + Mascotas + Fumar + Estudio) / 5 ) * 100
Figura 2. Proceso de cálculo de compatibilidad y generación de candidatos.

3.2 Infraestructura IA: Google Gemini

Como avance estratégico en el Sprint 3, se ha integrado el SDK @google/genai. Aunque el sistema ya opera sobre reglas deterministas, se ha dejado listo el puente tecnológico para el procesamiento cognitivo de descripciones de vivienda.

  • Inyección de Secretos: Configuración en vite.config.ts para el manejo seguro de la GEMINI_API_KEY.
  • Extracción de Reglas: Capacidad técnica para analizar texto libre (descripciones) y detectar automáticamente reglas de convivencia no estructuradas.
  • Análisis de Sentimiento: Infraestructura preparada para evaluar la calidad de los comentarios y ratings en las publicaciones.
Sección IV · Operaciones y Datos

Gobernanza y Modelo Relacional

La integridad del sistema se mantiene mediante un estricto control administrativo y un modelo de datos normalizado que evita redundancias y garantiza la integridad referencial.

4.1 Dashboard de Administración Estudiantil

Se implementó la ruta protegida /admin que permite al personal universitario verificar la identidad de los usuarios registrados, mitigando el riesgo de perfiles falsos.

Flujo de Verificación (Secuencia)

  • Admin consulta la lista de usuarios con estado is_verified = 0.
  • Ejecución del endpoint POST /api/admin/verify/:id.
  • Actualización atómica en SQLite y refresco de estado en el cliente vía React.
